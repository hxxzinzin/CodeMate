# AI Development Log

CodeMate는 AI 코딩 도구(Claude Code)를 활용해 개발합니다.
이 문서는 주요 기능을 개발할 때 **누가 무엇을 제안하고 결정했는지**를 기록합니다.

- AI의 제안은 그대로 반영하지 않고, 검토·테스트·수정을 거친 뒤 채택 여부를 결정합니다.
- 기술적 의사결정의 상세한 근거는 [decisions.md](./decisions.md)에 기록합니다.
- 실제로 일어나지 않은 작업(실행하지 않은 테스트, 하지 않은 검토 등)은 기록하지 않습니다.

## 2026-10-01 — 전체 설계 및 개발 방식 결정

관련: ADR-001 ~ ADR-007

### 요청한 내용
- 장기간 사용할 수 있는 개인 맞춤형 코딩테스트 학습 플랫폼(CodeMate)의 요구사항을 마스터 프롬프트로 정의했다.
  - AI는 정답을 주지 않는 "코치" 역할을 한다.
  - Java/C 비율, 규칙 기반 adaptive difficulty, Skill 시스템을 둔다.
  - 무료 플랜(Vercel + Supabase + Gemini)만 사용한다.
- 코드를 작성하기 전에 아키텍처, DB 스키마, RLS, 추천 알고리즘, 비용 전략, Phase 계획을 먼저 제시하도록 요청했다.

### AI가 제안한 내용
- 시스템 아키텍처, ERD, 테이블 스키마, RLS 전략을 제시했다.
- 원래 요구사항에서 다음을 변경하자고 제안했다.
  - 힌트·해설을 비공개 테이블로 분리한다.
  - `user_problem_progress` 테이블을 추가한다.
  - `c_ratio` 컬럼을 없애고 `java_ratio`에서 계산한다.
  - 태그 종류를 Skill 카테고리와 맞춘다.
- 오늘의 문제 추천에 가중치 점수 + 상위 5개 확률 선택 방식을 제안했다.
- 난이도는 수행 점수 기반으로 조정하고, Skill 점수는 지수이동평균 방식으로 계산하자고 제안했다.
- MVP는 자기 보고 채점으로 하고, Vercel 배포를 Phase 2로 앞당기자고 제안했다.
- 포트폴리오용으로 Issue / Milestone / PR / Conventional Commits 기반의 작업 흐름을 제안했다.
- 커밋에 AI Co-author 표기를 넣을지 질문했다.

### 수정하거나 거부한 내용
- 커밋마다 AI를 `Co-authored-by`로 자동 표기하는 방식은 거부했다.
  - 대신 README의 AI-assisted development 섹션, 이 개발 로그, ADR로 AI 사용을 투명하게 공개하기로 했다.
- CodeMate와 DataMate를 각각 별도 저장소로 개발하기로 했다.
  - GitHub 저장소 이름을 `TestSite`에서 `CodeMate`로 변경했다.
- 프로젝트별로 API 키를 따로 발급하고, 키 값은 직접 설정하기로 했다.

### 최종 결정
- 제안된 설계를 기본안으로 승인하고, Phase 1부터 단계적으로 구현한다.
- 각 Phase는 Issue → 브랜치 → 작은 커밋 → PR 흐름으로 진행한다.

### 검증
- 해당 없음 (설계 단계, 아직 코드 없음)

## 2026-10-01 ~ 10-02 — Phase 2: Supabase, Auth, 첫 배포

관련: #4 ~ #8, PR #30 ~ #36, ADR-008, ADR-009

### 요청한 내용
- Phase 2 진행을 요청했다.
- 진행 중에 작업 방식을 바꿨다.
  - PR은 검증 후 바로 merge한다.
  - 단계별 리뷰 대신, 전체 개발이 끝나면 공부용 정리 문서("비법서")를 받기로 했다.
- Supabase 프로젝트 생성 화면의 Security 옵션을 어떻게 골라야 하는지 질문했다.
- 진행 안내를 영어가 아닌 한국어로 해달라고 요청했다.

### AI가 제안한 내용
- DB 변경을 클라우드에 바로 적용하지 않고 로컬 Supabase(Docker)와 pgTAP 테스트로 먼저 검증하자고 제안했다.
- 기본 권한을 모두 회수하고 GRANT와 RLS를 테이블마다 명시하자고 제안했다.
- 프로젝트 생성 시 "새 테이블 자동 노출" 옵션을 끄자고 추천했다.
  - 이 추천 때문에 클라우드에서 service_role 권한이 빠지는 문제가 생겼다. (아래 "검증" 참고)
- Supabase 새 키 형식(publishable/secret), Next.js 16 `proxy.ts`, `/api/health`를 제안했다.
- 구현 중 AI가 직접 찾아 고친 문제
  - health 체크가 자동 재시도 때문에 12초 이상 걸리던 문제
  - 환경변수 누락 시 사이트 전체가 500이 되던 문제
  - 빌드 시 로그인 상태가 고정된 정적 페이지가 만들어지던 문제
  - `try/catch`가 Next.js 내부 에러를 삼키던 문제

### 수정하거나 거부한 내용
- 검증 환경으로 로컬 Supabase와 클라우드 직접 적용 중 로컬 Supabase를 선택했다.
- Phase별 리뷰 방식 대신, 개발 완료 후 학습용 정리 문서를 받는 방식으로 바꿨다.

### 최종 결정
- Supabase(서울 리전), Google OAuth, Vercel 배포를 직접 설정했다.
  - 키 발급과 입력은 직접 했다.
- Phase 2를 완료했다: https://code-mate-gold.vercel.app

### 검증
- AI가 실행
  - pgTAP 35개 통과
  - 정책을 일부러 망가뜨려 테스트가 실패하는지 확인
  - 로컬·클라우드 REST API 접근 확인
  - 장애 주입(DB API 컨테이너 중지)
  - 로컬 테스트 계정 로그인·로그아웃, open redirect 차단
  - 배포 사이트 점검, 클라이언트 번들 비밀 키 노출 검사
- 직접 확인: 로컬과 배포 사이트에서 실제 Google 계정 로그인 성공
- 첫 실제 로그인 후 가입 트리거 결과를 확인하다가 클라우드에서만 service_role이 `permission denied`가 나는 문제를 발견했다.
  - migration으로 권한을 명시해 수정했다. (ADR-009)
  - 로컬 테스트만으로는 환경 차이를 잡을 수 없다는 교훈을 얻었다.

## 2026-10-02 — Phase 3~6: 문제 시스템, 에디터, 제출, AI 코치

관련: #9 ~ #19, PR #38 ~ #48, ADR-010

### 요청한 내용
- 각 이슈를 순서대로 진행하도록 요청했다.
- Gemini 모델을 고르기 위해 테스트 명령을 요청했고, 이후 "직접 실행해달라"고 요청했다.
- 진행 안내와 할 일 안내를 한국어로, 짧은 단계로 해달라고 다시 요청했다.
- 개발이 끝나면 겪은 에러와 이슈까지 정리한 학습 문서를 만들어 달라고 요청했다.

### AI가 제안한 내용
- **문제 콘텐츠**
  - 문제를 코드처럼 관리하는 구조(content/problems)를 제안했다.
  - 정답 코드를 실제로 실행해 검증하는 스크립트를 제안했다. (Java는 로컬 JDK, C는 Docker)
  - 29문제는 AI 서브 에이전트 3개가 나누어 작성했고, 공통 형식과 검증 스크립트로 품질을 확인했다.
- **에디터·제출**
  - Monaco 지연 로딩, localStorage 자동 저장, 자기 보고 채점(ADR-003)을 제안했다.
  - 화면이 보이는 동안만 재는 풀이 타이머, KST 기준 streak를 제안했다.
- **AI 코치**
  - 정적 힌트를 먼저 보여주고 AI 힌트를 그다음에 두는 구조를 제안했다.
  - 완성 코드를 서버에서 한 번 더 걸러내는 이중 방어를 제안했다.
  - "정답 보기"는 AI 생성 대신 검증된 정답 코드를 쓰자고 제안했다.
  - 응답 캐시와 하루 한도(로그인 20 / Demo 3 / 전체 200)를 제안했다.
- **모델 선택**
  - 후보 4개를 실측해서 `gemini-3.5-flash-lite`를 기본 모델, `gemini-3.1-flash-lite`를 예비 모델로 추천했다. (ADR-010)

### 수정하거나 거부한 내용
- 모델 선택은 AI가 측정한 결과(최신 모델 503 반복, 생각 토큰으로 답변 잘림)를 보고 추천안을 받아들였다.
- 설정 변경은 역할을 나눴다.
  - Vercel의 `GEMINI_MODEL`은 직접 변경했다.
  - `.env.local`의 모델 이름 한 줄은 AI가 변경하도록 했다. (키는 건드리지 않음)

### 최종 결정

### 검증

  - 실제 Gemini 호출로 리뷰 품질과 프롬프트 인젝션 거절 확인

## 2026-10-02 — Phase 7~9: Skill, 적응형 난이도, 오늘의 문제, 대시보드

관련: #20 ~ #25, #56, PR #50 ~ #57, ADR-004, ADR-011 ~ ADR-013

### 요청한 내용
- 각 이슈를 순서대로 진행하도록 요청했다. ("응 #N 진행해줘")
- 수정·커밋·merge는 확인 없이 바로 진행하도록 요청했다.
- 보고와 할 일 안내를 한국어로 해달라고 다시 요청했다. (#25 보고가 영어로 작성됨)

### AI가 제안한 내용
- **Skill (#20, #21)**
  - 수행 점수 p(정답, 풀이 시간, 힌트, 시도 횟수, AI 리뷰·정답 확인)를 제안했다.
  - Skill 점수를 목표 점수 p × (40 + 12 × 난이도)를 향한 지수이동평균으로 갱신하자고 제안했다.
  - Java/C 개념 태그는 실제로 제출한 언어일 때만 반영하자고 제안했다.
- **적응형 난이도 (#22)**
  - D' = D + 0.4 × 가중치 × (p − 0.65)를 제안했다. (한 번에 ±0.3, 1~5)
  - 그 문제의 첫 제출이나 처음 해결했을 때만 조정하자고 제안했다. (같은 문제 반복 실패·복습으로 흔들리지 않게)
- **오늘의 문제 (#23)** — ADR-011
  - 언어 비율 → 난이도 구간(70/20/10) → 후보 필터 → 가중치 점수 → 상위 5개 중 점수 비례 선택 순서를 제안했다.
  - 사용자·날짜·뽑기 횟수로 시드를 만든 재현 가능한 난수를 제안했다.
  - 새로 뽑기 하루 2회, 추천 이유 저장, unique 제약으로 동시 요청 처리를 제안했다.
- **대시보드 (#24)** — ADR-012
  - 통계를 DB 함수(security invoker)로 집계하자고 제안했다.
  - 제출할 때만 갱신되는 streak를 화면에서 보정하자고 제안했다. (이틀 이상 쉬면 0)
- **학습 현황 (#25)** — ADR-013
  - Skill·난이도 변화량을 제출 이력에 같이 기록하자고 제안했다.
  - 차트는 라이브러리 없이 SVG로 그리자고 제안했다.
- **설정 저장 (#56)**
  - #25 작업 중 설정 화면의 언어 비율이 저장되지 않는 것을 발견했다.
  - 별도 이슈로 만들자고 제안했다.

### 수정하거나 거부한 내용
- **난이도 테스트 가정 수정**
  - 처음에는 "정답률 2/3이면 난이도가 유지된다"고 가정하고 테스트를 작성했는데, 테스트가 실패했다.
  - 계산해 보니 균형점은 약 70%였고, 설계 의도("약간 어려운" 구간 유지)에 맞는 동작이었다.
  - 그래서 공식이 아니라 테스트를 실제 동작을 문서화하는 형태로 고쳤다.
- **커밋 정리 (#56)**
  - 미리 스테이징해 둔 파일 삭제가 다른 커밋에 섞여 들어갔다.
  - push 전에 발견해 커밋을 다시 나눴다.
- 사용자가 직접 수정하거나 거부한 제안은 없었다.

### 최종 결정
